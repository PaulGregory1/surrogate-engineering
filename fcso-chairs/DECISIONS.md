# Decisions

One line per decision not settled by SPEC.md or the paper: what, and why.

- Project lives in `~/Documents/fcso-chairs`, Python 3.12 venv managed by uv: Python 3.10+ required, 3.12 is the newest available locally.
- Data is fetched by HTTP range requests on the Google Drive zips (`remotezip`), chair folder only: occupancies.zip is 548 GB and surfaces.zip 52 GB, more than the free disk (44 GB).
- Only the per-shape `scale` (.npy) and split lists are taken from occupancies.zip, plus `.npz` occupancy files only for shapes we optimize: `util/shapenet.py` multiplies surface points by that scale before encoding, so it is required to match the training distribution.
- `torch_cluster.fps` is replaced by a pure-PyTorch FPS registered in `sys.modules` (`fcso/compat.py`), starting from the first point instead of a random one: no edit to third_party, and deterministic encodings.
- Model-only checkpoint copies (`*-model.pth`) are saved next to the originals: loading skips 2 GB of optimizer state each time.
- Chairs to optimize come from the `test` split: the AE and the prior were trained on `train`.
- Latent normalization: the EDM prior was trained on `ae.encode(surface)[1]` = a KL posterior **sample**, with no scaling factor (`engine_class_cond.py`), and `EDMPrecond.sigma_data = 1`; encoded test-chair means have std ≈ 0.93–1.01, so latents are fed to the prior as is, no rescaling.
- Optimization starts from the posterior mean (SPEC), computed by `Prior.encode_posterior`, which mirrors `KLAutoEncoder.encode` up to `mean_fc`/`logvar_fc` (same logvar clamp) instead of patching the repo's `encode`, which always samples.
- The diffusion prior's training set used `AxisScaling` augmentation (random per-axis 0.75–1.25, renormalized to max |x| = 1, 0.005 jitter; `util/datasets.py`); we encode without it, like the repo's val/test path: test chairs times `scale` already span max |x| ≈ 1.
- Surface subsample for encoding: 2048 points drawn without replacement from the 100k cloud with `np.random.default_rng(seed)`, seed 0 by default (the repo draws unseeded), so encodings are reproducible.
- Grid convention: linspace(-1, 1, R) per axis, 'ij' order, volume indexed [x, y, z] (`prior.make_grid`); equivalent to the repo's `meshgrid` + `permute(1, 0, 2)`. Bounds [-1, 1]^3 from `eval.py`/`sample_class_cond.py` and paper App. F.1.
- Occupancy sign: positive logit = inside (`eval.py` compares `logits >= 0` to occupancy labels); meshes are extracted at level 0.
- Meshes for renders/metrics: `skimage.measure.marching_cubes` at 128^3 (SPEC) rather than the repo's 129^3 + PyMCubes; faces oriented so the trimesh volume is positive.
- Render camera: orthographic, 3/4 front view from (2.6, 1.6, -3.4) looking at the origin, y up, parallel scale 1.3, white background, fixed for every render (`fcso/mesh_render.py`): chairs face -z (backrest at +z).
- Reconstruction quality metric: the repo's `eval.py` Chamfer (sum of the two mean NN distances, 100k mesh samples vs the full surface cloud) and F-score at 0.02; IoU skipped because it needs the 11 MB occupancy files.
- The interactive viewer uses three.js from a CDN in a single HTML page: it opens by double-click, no server or build step (user request of Oct 8, see SPEC.md Evaluation).
- `splits/opt.txt`: candidates = first 48 of `np.random.default_rng(0).permutation(test ids)` (`scripts/pick_candidates.py`), 10 picked by eye for variety (thin legs, armrests, pedestals, one cantilever, two bulky upholstered); debug set = first 3 (thin-leg armchair, pedestal office chair, thin-leg dining chair).
- MPS: no op fell back to CPU in encode, decode or one EDM denoiser forward (no fallback warning with `-W default`); float64 is unsupported on MPS, so the repo's `edm_sampler` (casts to float64) cannot run there as is.
- Correction schedule "rho = 7 truncated to [0, sigma_start]" (`correct.correction_sigmas`): the repo's EDM formula with sigma_max := sigma_start, same sigma_min 0.002 and rho 7, N values then 0, so exactly N ODE steps (the last Euler step, 0.002 -> 0, returns D(x; 0.002)), as edm_sampler does with t_N = 0.
- Sampling from noise (`correct.edm_sample`): float32 port of the repo's `edm_sampler` (18 steps, Heun except the last step, S_churn 0, sigma 80 -> 0.002 -> 0), because MPS rejects float64; same arithmetic otherwise.
- All prior/correction noise is drawn on the CPU with a seeded `torch.Generator`, then moved to MPS: reproducible across devices; `correct()` takes a fresh seed per call (FCSO will pass a new one per cycle).
- Milestone 3 volume check uses a no-grad estimate, 8 x fraction of 64^3 grid logits > 0 over [-1, 1]^3, not the differentiable sigmoid estimator of milestone 4 (user instruction for milestone 3); marching-cubes mesh volumes at 128^3 are logged alongside.
- Milestone 3 correction is run with 3 noise seeds (0, 1, 2) per chair to separate the systematic volume change from noise; the 5% criterion is judged on every run.
- Phase 2 guidance API (`correct.correct(..., guidance=g)`): g(x, sigma, denoised) returns a term added to d before the step (d_guided = d + g, SPEC sign); `ode_step` logs |d| and |g| per step for lambda calibration. Not implemented yet (milestone 6).
- MPS: no op fell back to CPU during EDM sampling (18 Heun steps) or the 10-step correction (no fallback warning with `-W default`, logs/m3_*.log).
- Milestone 3 criterion (unguided correction changes volume < 5 %) is met on 8/10 opt chairs only; the 2 thin-frame failures (+9.5 %, +15 %) are accepted, not tuned away: σ_start stays at 0.25 (Table 6) and guidance (milestone 6) is expected to pin V; to be reported in REPORT.md.
- Volume estimator grid (`fcso/volume.py`) is cell-centered, points -1 + (i + 1/2)·2/R, so |B|·mean is the midpoint rule over [-1, 1]^3: on the vertex grid linspace(-1, 1, R) (mesh/decode convention) |B|·mean is biased by (1 - 1/R)^3 = -4.6 % at 64^3, which made 7824e41c (-5.1 %) and 447856e1 (-5.5 %) fail the ±5 % mesh test; the bias is a constant factor, so V/V_initial is unaffected either way (`centered=False` keeps the vertex grid).
- β stays 1 (SPEC default): β = 10 changes V(z_s) at 64^3 by at most 1.1 % on the 10 opt chairs (logits span about ±30, under 1 % of grid points have |logit| < 2), and the estimator is within ±5 % of the mesh on all 10, so the SPEC's "increase β" condition is not met.
- The ±5 % estimator-vs-mesh test runs on all 10 opt chairs instead of 5 (SPEC minimum): it costs about 30 s and covers the thin-frame chairs flagged at milestone 3.
- 48^3 is not allowed during optimization (`volume.RES48_ALLOWED = False`, `OPT_RES = 64`): on the 3 debug chairs 48^3 differs from 64^3 by -3.2 / +5.7 / +17.1 % (SPEC threshold 2 %); thin legs alias at 0.042-wide cells.
- gradcheck runs in float64 on the CPU on a random 3-dim slice z_s + Σ a_k u_k (6^3 grid, 50-query chunks, β = 0.1 so most queries carry gradient): a full gradcheck over the 4096 latent entries would need 8192 decoder passes; β = 1 is checked by central differences on 16^3 (relative error 8e-7 along the gradient, 6e-8 along a random direction).
- Gradient of a function F(V) (e.g. (V - c)^2 for guidance): `Volume.backward(z, fn)` computes V, then w = dF/dV, then h.backward(w · h_leaf.grad): exact because V_b depends on z_b only, and it costs no extra decoder pass; `Volume.__call__` wraps the same chunked steps in a `torch.autograd.Function` so V can also be used in any autograd expression.
- Query chunk = 32768 by default: value+grad at 64^3 takes 0.52 s (16384: 0.53 s, 65536: 0.87 s) with a peak MPS allocation of 1.40 GB (1.28 / 1.65 GB).
- Chairs are not batched through the volume estimator: a B = 3 value+grad step takes 2.44 s against 3 × 0.52 s one by one, and pushes the process footprint to 5.6 GB (chunk 32768) or 9.1 GB (chunk 65536).
- Peak memory of a gradient step is reported as: MPS current allocation sampled after each chunk forward and around the trunk backward (`Volume.trace`), MPS driver allocation after the step (empty_cache before), process peak RSS (ru_maxrss) and the `/usr/bin/time -l` peak footprint of a process doing only 64^3 steps; torch 2.14 has no MPS max-allocated counter.
- MPS: no op fell back to CPU in the volume value, value+grad or chunked backward (no fallback warning with `-W default`, logs/m4_pytest.log, logs/m4_volume_check.log).
- **Phase 1 optimizer = Adam, lr 0.005, state reset at the start of every 15-step cycle, for every method (GD, GD λ_reg, FCSO, FMG has no Phase 1)** (`configs/base.yaml`): literal SGD at η = 0.005 (Eq. 5) moves V by 0.11 % (2b5953c9) and 0.07 % (20b0a820) in 60 steps (`runs/debug/probe_sgd_lr0.005/`, `logs/debug_probe_sgd_lr0.005.log`; |dV/dz| ≈ 0.02-0.03), i.e. ≈ 40-60k steps to 70 % against a 1000-step budget, because our V is ≈ 0.1-0.3 (not the paper's ≈ 4.5) so the gradient scale is not the paper's; Adam's step (≈ lr per coordinate) does not depend on that scale, so η = 0.005 keeps its Table 6 meaning in latent units. Adam at 0.005 reaches 70 % in 90 steps (2b5953c9) and 165 steps (f215c608) (`runs/debug/probe_adam_lr0.005/`), so η was not raised.
- Adam state is also reset every cycle in GD (where nothing moves z between cycles): GD is then exactly FCSO with Phase 2 removed (App. B, "omitting Phase 2 ... reduces the pipeline to standard gradient descent"), and checkpoints at cycle boundaries need no optimizer state.
- GD λ_reg: the regularization gradient 2 λ_reg (z - z_s) is added to dV/dz before the Adam step, with V in absolute units (not V/V_initial), λ_reg = 1e-3 as in the SPEC.
- Gradient-step budget: when 1000 is not a multiple of M = 15, the last cycle is truncated (66 × 15 + 10 steps); r and the thresholds are checked after every cycle only (SPEC), so a snapshot's V/V_init can overshoot its threshold and one cycle can cross several thresholds (they then share the same latent).
- Snapshot wall time counts only optimization work (gradient steps, Phase 2, the per-cycle 64^3 r evaluation), accumulated across resumes; not encoding, checkpoint I/O or evaluation meshes. The r evaluation is a separate 64^3 `Volume.value` pass after every cycle (~0.24 s), even for GD, so all methods pay the same bookkeeping.
- Snapshots are taken from the first cycle with r ≥ threshold; the initial shape is snapshot "0" (step 0, time 0); a run stopped on the budget also gets its final latent evaluated ("final" column).
- Stray components = every connected component of the 128^3 marching-cubes mesh except the largest by volume (`trimesh.split(only_watertight=False)`); stray share = their volume / total component volume (`fcso/metrics.py`).
- Chamfer to the initial shape: 10k surface samples per mesh (different seeds for the two meshes), sum of the two mean unsquared NN distances (eval.py convention, as at milestone 2). Its floor between two samplings of near-identical meshes is ≈ 0.025 (SGD probe, V/V0 0.999), so values below ≈ 0.03 mean "no visible change".
- Evaluation renders colour stray components red (`render_grid(..., color_strays=True)`), as the SPEC asks for the viewer.
- Option B guidance (`correct.VolumeGuidance`): g = λ ∇_x (V(y) − c)², y = x (mode `noisy`, default, denoiser under no_grad) or y = D(x; σ) (mode `x0`, a second denoiser forward with grad on a detached leaf copy of x, then the chunked `Volume.backward` through it); added to d (d_guided = d + g, SPEC sign). With Heun the guidance is evaluated at both stages. Model parameters are frozen and never get a `.grad` (`tests/test_guidance.py::test_no_grad_reaches_params`).
- c = V(ẑ) at 64³ (the same estimator and grid as Phase 1 and r), recomputed after Phase 1 by a no-grad pass, as Algorithm 1 line 7.
- Guidance sign test (`tests/test_guidance.py`): one Euler step from x = z_s + 0.25 ε on the 3 debug chairs, c = 0.8 V(x) and 1.2 V(x) (c off V(x) so (V − c)² has room to move), λ set so |g| = 0.3 |d|; guided must beat unguided, and −λ must do worse than +λ; both modes. Passes (logs/m6_pytest.log, runs/m6/test_results.json).
- λ calibration states: ẑ after 1 and after 3 Phase-1 cycles (15 / 45 Adam steps from z_s) of each debug chair, 3 noise seeds each (18 first-step measurements), because the ratio |d| / |∇(V − c)²| at the first step depends on how far V(x) lands from c after the noise injection, which varies by noise draw and progress (`scripts/calibrate_guidance.py`, runs/m6/calibration_noisy.json).
- FMG counts its N = 10 guidance gradients per repetition as gradient steps against the 1000-step budget (100 repetitions max); FCSO's Phase 2 guidance gradients are not counted (only Phase 1 steps are, as in Algorithm 1 / Table 5), so the budgets match "gradient steps on the objective" for each method; wall time is the fair cost measure and is reported for all.
- FCSO without guidance = `configs/fcso_noguide.yaml` (method fcso, guidance none, λ 0); FMG = `configs/fmg.yaml` (same guidance mode and λ as FCSO, c = 0.97 V_current).
- Phase 2 noise seed of cycle k = seed · 100003 + k with seed = 0 for every chair (fixed and logged per shape in cycles.json `noise_seed`); ε is redrawn every cycle.
- **Guidance scale, noisy mode: λ = 1000** (`configs/fcso.yaml`; ×3 = 3000 and ÷3 = 333 run as `fcso_lamx3`, `fcso_lamd3`). λ₁ = |d| / |∇_x(V − c)²| at the first ODE step over 18 states (3 chairs × cycles 1, 3 × seeds 0-2): median 2.5e3, range 4.8e2–2.0e4 (|d| ≈ 41-45 everywhere, the gradient varies 40× with how far the noise pushes V(x) from c). λ = 1000 gives |g|/|d| at step 0 of 0.14-1.09 (median ≈ 0.4) on the full-correction states, the SPEC window 0.1-1; λ = 3000 exceeds 1 on 3/6. Evidence: runs/m6/calibration_noisy.json, logs/m6_calibrate_noisy.log. Effect on one correction (mean V_after/c over 3 seeds, unguided → λ 1000 → 3000): 2b5953c9 cycle 3: 1.35 → 1.29 → 1.15; 20b0a820 cycle 3: 1.26 → 1.20 → 1.10; f215c608 cycle 3: 1.24 → 1.23 → 1.22: inside the window, noisy guidance removes only part of the wash-out, least on the thin chair.
- **Guidance scale, x0 mode: λ = 1e4** (variant `fcso_x0`): λ₁ median 3.5e4, range 4.2e3–1.3e6 (the denoiser Jacobian damps ∇V at σ = 0.25); λ = 1e4 gives |g|/|d| at step 0 of 0.11-1.79 (median ≈ 0.3). x0 guidance pins V much better per unit of |g|/|d|: at λ = 3e4 (step-0 ratio 0.33-5.4), V_after/c = 1.00 / 1.01 (2b5953c9), 1.00 / 1.01 (20b0a820), 1.04 / 1.10 (f215c608) (cycle 1 / 3). runs/m6/calibration_x0.json, logs/m6_calibrate_x0.log.
- Heun was checked on single corrections only, not as full FCSO runs: on the cycle-3 states of the 3 debug chairs, Heun gives the same wash-out as Euler (mean V_after/c, unguided / λ 1000 / λ 3000: 2b5953c9 1.37 / 1.30 / 1.15 vs Euler 1.35 / 1.29 / 1.15; 20b0a820 1.27 / 1.21 / 1.11 vs 1.26 / 1.20 / 1.10; f215c608 1.26 / 1.25 / 1.22 vs 1.24 / 1.23 / 1.22) at 1.9× the Phase 2 cost (11.2 vs 5.9 s per guided correction), as milestone 3 found for the unguided ODE (runs/m6/calibration_noisy_heun.json, logs/m6_calibrate_noisy_heun.log).
- x0 mode was run at λ = 1e4 (calibrated) and ×3 = 3e4, not ÷3 = 3.3e3: at 1e4 the two thin/pedestal chairs already stall because the correction gives back what Phase 1 gains, and a weaker λ only weakens the term that counters that wash-out (monotone in every calibration correction, runs/m6/calibration_x0.json); noisy ÷3 confirmed this (20b0a820 stalls at 0.44, f215c608 at 0.82).
- Milestone 6 criterion is not met by any SPEC-sanctioned variant (λ, ×3, ÷3, x0, Heun); per SPEC "Expected outcome" nothing was tuned further (σ_start, N, M, lr, β untouched).
- **Recommended FCSO for milestone 7: `configs/fcso_x0.yaml` (x0 guidance, λ = 1e4)**, with `configs/fcso.yaml` (noisy, λ = 1000, the SPEC default mode) as an extra row if time allows: same calibration rule, same quality on the 3 debug chairs (1 component at 70 % / final on all 3 chairs in both modes; 20b0a820 has transient 2-3 components at 30-50 % in both), and 3.3× faster to 70 % on 2b5953c9 (143 s vs 473 s), 2b5953c9 being the only chair either reaches 70 % on. The SPEC names x0 as a variant "often more stable"; choosing it among the sanctioned variants is not a further tuning of hyperparameters. ×3 settings are not recommended: noisy λ 3000 shreds f215c608 and 2b5953c9 like GD, x0 λ 3e4 splits 20b0a820 in three at 70 %.
- FMG uses the same guidance as the recommended FCSO (x0, λ 1e4; `configs/fmg.yaml`): with noisy λ = 1000 a correction gives back +7 to +35 % of V even with c = V (calibration), so FMG could not move toward 0.97 V at all.
- `scripts/summarize_runs.py` tabulates evaluated runs (64³ ratio, 128³ mesh ratio, components, stray share, Chamfer at each snapshot) into runs/m6/summary.{json,md}; milestone 7 can reuse it.
- **Milestone 7 main FCSO run = `configs/fcso_x0.yaml` (x0 guidance, λ = 1e4)**, decided on Oct 8: an allowed SPEC variant ("decode D(x; σ) ... often more stable"), λ calibrated by the SPEC rule at milestone 6 and not tuned since; GD = `configs/gd.yaml` (λ_reg = 0) is the "without correction" method; `configs/fcso.yaml` (noisy, SPEC default) is an optional extra row.
- Milestone 7 reuses the 3 debug chairs of `runs/{gd,gd_reg,fcso_x0,fcso}` from milestones 5-6: their saved configs equal the current YAMLs, and a rerun with the same seeds would only repeat them.
- `evaluate_run` saves each run's 128³ evaluation meshes (`meshes.npz`, float32 vertices / int32 faces per snapshot label) so `scripts/make_report.py` builds grids and viewer meshes without decoding, i.e. without competing for the GPU with a run whose wall time is being measured.

- Report viewer (`scripts/make_report.py`, `scripts/viewer_template.html`): three.js 0.147.0 UMD build + its `examples/js` OrbitControls from jsDelivr (the last release that ships non-module examples, so plain `<script>` tags work on file://); one WebGL renderer with scissor viewports and one shared orthographic camera (same view as the PNG renders), one OrbitControls per cell on that camera with targets kept in sync.
- Viewer meshes: VTK quadric decimation through PyVista (`PolyData.decimate`, already installed, no new dependency) to ≈ 20k faces per cell, largest component and stray components (merged) decimated separately with the same ratio so fragments survive; positions quantized to uint16 over [-1, 1], indices uint16 when < 65536 vertices; the initial mesh is stored once per chair (same z_s for every method).
- "final" column (grid PNG, trajectories, viewer) = the 1000-step budget state of runs that never reached 70 %, so stalled chairs stay visible next to the empty "not reached" cells.
- playwright (pip package only, driving the installed Google Chrome, no browser download) is installed in the venv for the headless viewer check `scripts/check_viewer.py`; it is not used by the pipeline.
- The report adds a paired quality table (`make_report.paired_quality`): FCSO vs GD stray components, stray share, whole count and Chamfer on only the chairs where both reached the threshold, because the per-method means cover different chair subsets (FCSO reaches 70 % on 6 chairs, GD on 10); the SPEC's per-method means are kept as they are.
