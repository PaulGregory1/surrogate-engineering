# flow-surrogate

A 2-D lattice-Boltzmann solver, five surrogates fitted to it, and a shape optimiser that
back-propagates through the surrogate to minimise drag at constant area — then checks the
answer against the solver.

Everything runs on a laptop (Apple M-series, MPS): ~25 min to generate the dataset, ~4 min
per model to train. All numbers below are regenerated by `scripts/03_report.py` into
[`RESULTS.md`](RESULTS.md), which is committed along with `results/*.json` and `figs/`, so
none of it has to be re-run to be read.

![Problem setup](figs/setup.png)

*(a)* the channel, its boundary conditions and the only dimensionless group, $Re$;
*(b)* ten members of the shape family, all at **exactly** the same enclosed area;
*(c)* what the network sees, a squashed level set; *(d)* the rasterisation trick that
keeps the whole pipeline differentiable.

## Results

640 solver runs, 128 unseen test geometries; every neural model trained for the same 40
epochs, the ROMs fitted in seconds.

| | rel L2 (u, v, p) | C_d error | C_d worst case | vs LBM |
|---|---|---|---|---|
| POD + ridge (classic ROM) | 0.144 | 7.08 % | 19.5 % | 17 600x |
| POD + kernel ridge | 0.107 | 3.78 % | 13.8 % | 19 800x |
| FNO | 0.080 | 1.94 % | 8.8 % | 347x |
| U-Net | 0.081 | 1.15 % | 3.9 % | 772x |
| **U-Net + continuity loss** | **0.078** | **1.03 %** | **4.2 %** | 700x |

Gradient descent through the frozen surrogate cuts drag **18.6 % at constant area,
confirmed by the solver** — 4 000 design evaluations in 17 s against roughly 2 h of solver
time. The surrogate was **11.3 % wrong about its own optimum**, against 1.03 % on the test
split: minimising $\hat J = J + e$ actively seeks out the designs where the error is most
favourable, so the error at the optimum is not the error the model advertises. The design
is genuinely better; the surrogate's account of *how much* better is not trustworthy
without the verification. One round of active learning halves that gap without moving the
optimum — it buys reliability, not a better design.

The ROM is not a straw man: it trains for free, infers 25x faster, and its field error is
only 1.4x worse. Where it loses is the engineering quantity.

## Running it

```bash
uv venv --python 3.12 .venv && VIRTUAL_ENV=.venv uv pip install -e .
./.venv/bin/python run_all.py            # everything, ~2 h on an M-series laptop
```

or step by step:

```bash
python scripts/00_generate_data.py       # ~25 min  -> data/
python scripts/01_validate_solver.py     # ~4 min   -> results/solver_validation.json
python scripts/02_train_all.py           # ~60 min  -> runs/
python scripts/03_report.py              #          -> RESULTS.md, figs/
python scripts/04_optimize_shape.py      # ~6 min   -> results/optimization.json
python scripts/05_setup_figure.py        # ~2 s     -> figs/setup.png
python scripts/06_explainer_figures.py   # ~20 s    -> figs/*.png
python -m pytest tests -q
```

Add `--device cpu` anywhere to avoid MPS. `scripts/02_train_all.py --epochs 20
--skip-sweep` gives a usable smoke run in a few minutes. `data/` and `runs/` (the solver
dataset and the checkpoints, ~300 MB) are the only things left out of the repo.

## Layout

```
flowsurrogate/
  geometry.py    star-shaped bodies; NumPy path + differentiable Torch path
  lbm.py         batched, compiled D2Q9 solver
  data.py        generation, splits, normalisation, input channels
  models/        pod.py (ROM baselines), unet.py, fno.py
  train.py       shared training loop (masked loss, drag head, physics term)
  metrics.py     field / drag / continuity metrics
  evaluate.py    predictions -> numbers
  optimize.py    differentiable shape rendering + projected Adam + solver verification
  plots.py       figures
scripts/         00 generate · 01 validate · 02 train · 03 report · 04 optimise · 05-06 figures
run_all.py       the pipeline end to end (--quick / --force)
results/         committed metrics, read by RESULTS.md and by the platform
figs/            committed figures
```

The solver is verified before anything is learned from it: `scripts/01_validate_solver.py`
reproduces published cylinder drag to a few percent after the standard blockage correction,
and `results/solver_validation.json` carries the comparison.

This repo is consumed as a **read-only library** by the platform in
[`../engine-copilot`](../engine-copilot) — nothing there reimplements its physics.
